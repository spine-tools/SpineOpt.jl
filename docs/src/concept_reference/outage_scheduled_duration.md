The definition of the `outage_scheduled_duration` parameter triggers the creation of the [minimum scheduled outage duration constraint](@ref constraint_min_scheduled_outage_duration). It bounds the sum of the [units\_out\_of\_service](@ref var_units_out_of_service) variable over the optimisation window from below and from above, so that each unit is taken out of service for the scheduled duration (plus at most one time slice). The primary function of this parameter is thus to schedule maintenance outages for units. The model decides when the outages take place.

It can be defined for a [unit](@ref) and will then impose restrictions on the [units\_out\_of\_service](@ref var_units_out_of_service) variables that represent whether a unit is on maintenance outage at that particular time. The parameter is given as a duration value. When the parameter is not included, the aforementioned constraint will not be created, which is equivalent to choosing a value of 0.

To schedule maintenance outages using this functionality, one must activate the [units\_out\_of\_service](@ref var_units_out_of_service) variable. This is done by changing the value of the [outage\_variable\_type](@ref) to either `integer` (for clustered units) or `binary` for binary units or `linear` for continuous units. Setting [outage\_variable\_type](@ref) to `none` will deactivate the [units\_out\_of\_service](@ref var_units_out_of_service) variable and this is the default value.
